# Weekly 가이드 — 주간업무보고 + OKR

산출물: `20. Area/23. 주간보고·OKR/Weekly/YYYY_MMDD-MMDD_weekly-okr.md` **새 파일 1개** (예: `2026_0714-0728_weekly-okr.md`)

한 파일이 세 부분으로 구성된다:

| 부분 | 독자 | 서식 |
|---|---|---|
| Part 1: OKR | AI (Monthly/Quarterly 재료, 상세 아카이브) | 위키링크·정량 수치·상세 허용 |
| Part 2: 주간업무보고 | 사람 (사내 시스템/메일에 붙여넣어 제출) | 붙여넣기 즉시 제출 가능한 텍스트 |
| 관련 노트 | 탐색용 | 위키링크 모음 |

**Part 2가 이 스킬의 성패를 가른다. 사용자가 제출 전에 다시 고쳐 써야 하면 실패다.**
상세 내용의 저장소는 Part 1이고, Part 2는 그 증류본이다.

## 1. 기간 결정

```
사용자가 기간을 지정 → 그대로 사용.
지정 없으면:
  prev_end = Weekly/ 파일명(YYYY_MMDD-MMDD)들 중 가장 늦은 종료일
  start    = min(지난주 월요일, prev_end)   # 공백은 시작일을 당겨서 메운다
  end      = 오늘 (작성 당일 포함 — 보통 화요일에 작성)
```

- prev_end ≥ start(중첩)이면: 상단에 `> ⚠️` 중첩 blockquote를 넣고, 일별 활동의 해당 행에 `_(직전 주간 중첩)_` 표기. 상세 서술은 신규 구간 중심.
- 공백이 14일 초과이거나 중첩이 3일 초과면 계산 결과를 제시하고 사용자에게 확인.
- Weekly 폴더가 비어 있으면(첫 실행) 기간을 사용자에게 확인.
- **작성을 시작하기 전에, 결정된 기간과 근거를 한 줄로 보고한다.**

## 2. 소스 수집

날짜의 진실은 **파일명**이다. 노트의 `date created`는 몰아서 백필되므로 신뢰하지 않는다.

1. **데일리 노트** (뼈대: 날짜·주제) — `20. Area/23. 주간보고·OKR/23-1. Daily/YYYY-MM-DD.md`
   - 2026-05-07 이후 형식: `## Schedule` → `#### Event` 아래 불릿만 유효. `#### TODO` · `## Log` · `## Note-taking`(dataview)은 항상 빈 보일러플레이트 — 읽지 않는다.
   - 2026-05-06 이전 형식(과거 기간 재생성 시): `## Summary` · `## Schedule`(인라인 `#okr` 태그가 있으면 추론보다 우선) · `## Achievements` · `## TIL`.
   - `YYYY-MM-DD.md` 정규 파일명만 채택. `(conflict …)` 등 Drive 충돌 사본은 무시하고 발견 사실만 고지.
   - 기간 내 평일 데일리가 다수 부재/0바이트면 Google Drive 동기화 문제일 수 있다 — 경고하고 중단.
2. **작업 로그** (상세의 주 원천) — `10. Project/11. Log/*_log.md`
   - Grep으로 기간 내 `# [[YYYY-MM-DD]]` 헤딩이 있는 파일을 찾아 해당 날짜 섹션만 읽는다.
   - 같은 날짜 아래 세션 종료 스냅샷이 반복 기록된 파일이 있다 — 동일 사실은 1회만 채택하고, 서술이 상충하면(진행→완료) 파일 내 나중 서술을 채택.
3. **프로젝트·회의·세미나 노트** — `10. Project/**` · `20. Area/21. 팀 운영/` · `30. Resource/34. 세미나·교육/`
   - 기간 내 수정된 파일을 후보로 삼되, mtime은 Drive 동기화로 튈 수 있으니 후보 필터로만 쓰고 내용의 날짜 언급으로 기간 관련성을 확정.
   - 정량 수치·판정·산출물 노트 제목, 그리고 **Confluence/Jira/Figma URL**(Part 2 링크용)은 여기서 얻는다.

## 3. OKR 태그 추론 (Part 1용)

데일리 노트에는 `#okr` 태그가 없다(2026-03 이후). **태그는 항상 `okr-master.md`의 매핑 태그 표에서 추론한다.**

- 접두어 → 상위과제: `ai활용/`→1 · `제품/`→2 · `검토/`→3 · `신규/`→4 (과제 제목·가중치·KR 문안은 okr-master가 원본).
- 한 활동에 복수 태그면 ` · `로 병기. 어떤 태그에도 맞지 않으면(전사 행사·팀 회의·휴무 등) `#기타`.

## 4. 파일 골격

프론트매터는 아래와 **그대로 동일**하게:

````markdown
---
up: "[[주간보고·OKR]]"
index: "[[🏷 Output]]"
type: final
tags: []
---

# Weekly — YYYY-W{시작 ISO주}[/W{종료 ISO주}]

> 기간: YYYY-MM-DD (요일) ~ YYYY-MM-DD (요일)
> 휴무: M/D(요일, 사유) · … · 주말(M/D~D, M/D~D)
> ⚠️ (중첩 시에만) M/D~M/D은 직전 주간([[직전파일명|MMDD-MMDD]])과 중첩 — 해당 구간 상세는 직전 보고서에 기재. 본 보고서는 M/D 이후 신규 작업 중심.

---

# Part 1: OKR
(§5)

---

# Part 2: 주간업무보고
(§6)

---

## 관련 노트
(§7)
````

휴무 판정: 데일리 본문의 연차/휴가/휴무/반차/공휴일 언급이 근거다(공휴일 표를 하드코딩하지 않는다). 평일인데 데일리 파일 자체가 없으면 휴무로 단정하지 말고 질문 목록에 추가.

## 5. Part 1: OKR (AI·아카이브용)

### `## 일별 활동`

`| 날짜 | 활동 내용 | OKR 태그 | 상태 |` 표. 기간 내 모든 날짜가 행으로 존재해야 한다(휴무 포함).

- 날짜: `M/D (요일)`. 연속일 묶기 가능: `7/15~7/16 (수·목)`.
- 활동: ` / `로 구분. 위키링크 허용 — **표 안에서는 파이프를 `\|`로 이스케이프** (`[[노트\|표시명]]`).
- 상태: `✅ 완료` · `🔄 진행` · `—`(휴무) 세 값만.
- 휴무 행 예: `| 7/17 (금) | 제헌절 — 휴무 | — | — |`

### `## OKR별 완료 항목`

```markdown
### 상위과제 N: <okr-master의 과제 제목>

#### #okr/<축>/<세부>          ← 복수 태그 묶음이면 `#### #okr/a · #okr/b`

- **[[산출물 노트|업무 제목]] 또는 업무 제목** (M/D~M/D, 완료|진행 — 유형) · 부가 표기(요청자·저장소 등)
  - 세부 사실 불릿 — 정량 수치·트러블슈팅·의사결정 포함. 여기가 상세의 저장소다.
```

활동이 있는 상위과제·태그만 쓴다. 불릿 머리 이모지는 선택 사항.

### `## 주간 성과 요약`

`| 구분 | 내용 |` 표, 행은 완료 / 진행중 / 정량 지표. 정량 지표는 okr-master의 정량 지표 항목에 대응되게 센다.

### 구조

```
- **카테고리**                                        ← 불릿 + 굵게 (헤딩 아님)
  - [상태] 업무 제목 (M/D~M/D, 상태)                   ← 업무 1건 = 1줄, 2칸 들여쓰기
    - 하위 상세 (M/D, 상태)                            ← 필요할 때만 0~3개, 4칸 들여쓰기
```

- 카테고리 어휘: `AX` · `AI` · `한컴피디아` · `한컴어시스턴트` · `한컴데이터로더` · `Add-Ons` · `SDK` · `기타`. **내용이 있는 카테고리만 쓴다** — `(해당 없음)`으로 채우지 않는다. AX가 맨 앞, 기타가 맨 뒤.
  - **AX**: 소속 팀(AX기술팀) 수행 업무 전반 — Agentic OS, 사내 연동·자동화 구축, AI 기술 검토·비교·검증 포함.
  - **기타**: 세미나·시연 참석, 전사 행사, 타 프로젝트 기획서 검토, 연차·휴무.
  - 제품 카테고리(피디아 등)는 실제로 그 제품 업무를 했을 때만.
- 업무 제목: **명사형 보고체** — "~검토", "~구축", "~평가", "~작성". 목적·대상이 드러나게 ("회의록 자동 생성을 위한 온프레미스 STT 모델 비교/검증", "로컬 오픈소스 TTS 검토: Qwen3-TTS의 한국어 업무 문장 품질 평가").
- 모든 업무 항목에 `(날짜, 상태)` — `(7/28, 진행)` · `(7/22~7/28, 진행)` · `(7/24~, 진행)` · `(7/2~7/16, 예정)`. 연차는 날짜만: `개인 연차 (7/27, 7/31)`.
- 상태 접두어 `[완료]`/`[진행]`/`[예정]`은 업무 카테고리 항목에 붙인다. 기타의 단순 참석·연차에는 생략.
- **링크는 외부 URL만** (Confluence·Jira·Figma 등) — 노트에서 URL이 확인되는 업무에만 `[__[상태] 제목 (날짜, 상태)__](URL "URL")` 형식으로 제목 전체를 감싼다. URL을 모르면 일반 텍스트로 두고 지어내지 않는다.
- 예정 업무·다음 주 연차도 포함한다.

### 내용 선별 — Part 2에서 뺄 것

구현·과정 디테일은 Part 1의 몫이다. Part 2에는 **업무 단위와 결과**만 남긴다.

| Part 1에는 있고 Part 2에는 없어야 하는 것 | Part 2에 남기는 형태 |
|---|---|
| 테스트 건수, CER 수치, 함수·브랜치·파일명, 에러코드, 스캔 횟수 | (제거 — 필요하면 "정량 검증 완료" 수준) |
| 트러블슈팅 경과, 인프라 구성 나열 | "셋팅 및 기능 구축 (진행)" 한 줄 |
| 판정·의사결정의 근거 서술 | 판정 결과만 ("대체 불가 판정") |
| `[[위키링크]]`, 이모지, `%% %%` 주석 | (제거 — 링크는 외부 URL만, 위키링크는 관련 노트로) |

## 7. `## 관련 노트`

순서대로:

1. `[[okr-master]]`
2. 직전 위클리: `[[파일명|직전 주간 (M/D~M/D)]]`
3. 본문(Part 1·2)에서 다룬 노트 전부 — 경로 포함 링크 권장: `[[10. Project/…/노트|표시명]]`
4. **마지막 줄 = 기간 내 데일리 전부**: `[[YYYY-MM-DD]] · [[YYYY-MM-DD]] · …`

## 8. 자체 점검 (작성 후 필수)

- [ ] 프론트매터 4개 필드가 §4와 동일
- [ ] 파일명·제목(W주차)·`> 기간:`의 날짜가 서로 일치
- [ ] Part 1 일별 활동에 기간 내 모든 날짜 존재 (휴무 포함)
- [ ] Part 2: `[[` 0건 · 이모지 0건 · `%%` 0건 · `####` 0건 — 카테고리는 `- **…**` 불릿
- [ ] Part 2 모든 업무 항목에 `(날짜, 상태)` 존재, 빈 카테고리 없음
- [ ] 관련 노트 마지막 줄 = 기간 내 데일리 전부
- [ ] API 키·토큰·프로젝트 번호 등 시크릿 값 0건 (사실 서술만 — "키 노출 발견, rotate 권고"는 가능)
