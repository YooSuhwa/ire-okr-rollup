# ERP 공수(MBO) 가이드: 라우팅 전용

**정본은 vault 노트다**: `20. Area/23. 주간보고·OKR/erp md/ERP 프로젝트 공수 입력 가이드.md`
(사번·프로젝트 분류표·작업유형표·공수 배분 규칙은 사용자가 직접 관리하는 설정이므로 이 레포에 복제하지 않는다. 요청이 오면 **정본을 먼저 읽고 그대로 따른다.**)

이 파일은 새 보고 체계와의 연결 규칙만 담는다.

## 기간

- 사용자 지정이 기본. 지정이 없으면 **지난달 1일 ~ 말일**을 제안하고 확인받는다 (ERP 입력은 월 단위 관행: `erpmd_2026_0601-0626.md` 등).
- 같은 기간 파일이 이미 있으면 덮어쓰기 전에 사용자에게 확인 (정본 규칙과 동일).

## 소스 (정본의 우선순위를 새 체계에 맞게 적용)

1. **Weekly Part 1의 `## 일별 활동` 표** (1순위): 새 계약(weekly.md §5)에서도 표 구조가 동일하므로 그대로 파싱. 평일만 존재하고 주말 행이 없는 것이 정상.
2. **데일리 노트** (2순위): Weekly가 아직 커버하지 않는 구간(주로 월말 며칠)을 보강.
3. 데일리도 빈약하면 작업 로그(`11. Log/*_log.md`)의 해당 날짜 섹션. weekly.md §2의 제외 대상 규칙(생성 세션 기록·개인 프로젝트) 상속.

## 산출물

- 저장 위치·파일명·인코딩(UTF-8 BOM, CRLF, `|` 구분)은 정본 규칙대로: `erp md/erpmd_YYYY_MMDD-MMDD.md` + `_pipe.csv`.
- 공수 배분값은 초안이며 최종 수치는 사용자가 조정한다는 정본 원칙을 산출 후 한 줄로 상기시킨다.

## 상속 규칙

- 전역 문체 규칙(weekly.md): em dash 금지. 작업내용은 간결한 명사형(정본 규칙과 동일 방향).
- 가드레일(SKILL.md): 시크릿 값 금지, 기존 노트 수정 금지. 쓰기는 `erp md/`의 신규 파일만.
- 휴가·공휴일·주말은 행을 만들지 않는다 (근태 자동 연동, 정본 주의사항 4).
